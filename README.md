# posefit-vton

Виртуальная примерка одежды на данных Wildberries (BEFREE, женская линейка).

## Данные

Выгрузка в `data/` (в git не попадает): 3220 карточек товара, 18 категорий, 8.8 ГБ.

```
data/<Категория>/<Название SKU>/info.csv
                               /Фото товара/N.webp        23 377 кадров, все 900x1200
                               /Фото с отзывов/N_fs.webp  55 344 кадра, ~1000px по длинной стороне
```

Из этого получаются две ветки обучения:

* **студийная** — плоская выкладка вещи (последний кадр карточки) против съёмки
  на модели. Чистый фон, ровный свет, формат совпадает с VITON-HD;
* **wild** — та же вещь на реальном человеке из отзывов. Шумно, но именно эта
  ветка даёт разнообразие тел, поз и освещения.

## CPU-конвейер Ф0

```bash
make venv PYTHON=python3.12   # интерпретатор переопределяется под машину
make check    # диагностика машины: версии, GPU, наличие данных
make data     # манифест -> QC -> сплиты, ~6 минут на 78k кадров
make labeling # калибровочные наборы для ручной разметки
make test
```

Результат в `cache/` (тоже вне git):

| файл | содержимое |
|---|---|
| `manifest_sku.parquet` | строка на карточку: крой, группа одежды, поля `info.csv`, сплит |
| `manifest_images.parquet` | строка на кадр: размеры, резкость, phash, хэш содержимого, флаги пригодности |
| `splits.json` | train/val/test по группам кроёв, seed, проверка утечки, sha256 |

`preproc_root` (поза, parsing, маски, латенты — 5–10 ГБ, из них почти всё
латенты) в конфиге не задан намеренно: обращение к нему падает с внятной
ошибкой, пока каталог не выбран.

## GPU-этап

Стек собран на `transformers` и `diffusers` вместо канонического для VTON
набора (mmpose + detectron2): тот требует сборки mmcv под конкретную пару
torch+CUDA и detectron2 из исходников, здесь же веса тянутся с HuggingFace
и ничего не компилируется.

| стадия | модель | результат |
|---|---|---|
| `detect` | RT-DETR | боксы людей, их число, доля кадра — основа wild-фильтра |
| `parse` | SegFormer B2 clothes (ATR-18) | карта сегментации |
| `pose` | ViTPose | 17 точек COCO, видимость торса |
| `agnostic` | — | маска области, которую модель перерисовывает |
| `latents` | VAE ft-MSE | латенты fp16 |

```bash
export POSEFIT_PREPROC_ROOT=/mnt/data/posefit-preproc
make venv-gpu     # torch ставится отдельно, см. ниже
make models       # предзагрузка весов

python scripts/preprocess.py --stage detect   --fp16
python scripts/preprocess.py --stage parse    --fp16
python scripts/preprocess.py --stage pose
python scripts/preprocess.py --stage agnostic
python scripts/preprocess.py --stage latents  --fp16
```

Стадии запускаются по одной, а не одной целью `make`: им нужны флаги, и при
отладке важно видеть, какая именно команда упала.

torch не зафиксирован в `requirements-gpu.txt`: колесо зависит от версии CUDA
и ставится командой с pytorch.org под конкретную машину. Версию подскажет
`make check`.

Каждая стадия возобновляема — посчитанные файлы пропускаются, так что после
падения команда просто запускается заново. Для нескольких карт есть шардирование:

```bash
CUDA_VISIBLE_DEVICES=0 python scripts/preprocess.py --stage parse --shard 0/2 --fp16 &
CUDA_VISIBLE_DEVICES=1 python scripts/preprocess.py --stage parse --shard 1/2 --fp16 &
```

Рабочий набор — 43 251 кадр: 21 975 товара и 21 276 отзывов, после отсева
битых, шаблонных, повторов и кадров с недостоверной привязкой.

## Что выяснилось про данные

Три находки, определившие устройство конвейера.

**Фото отзывов повторяются под разными товарами.** Уникальны по содержимому
только 27 608 из 55 340 кадров (49.9%), и 34.5% лежат под несколькими
непохожими вещами сразу — привязка к SKU там недостоверна. После отсева
остаётся 21 276 кадров с однозначной меткой. Флаг `label_ok`.

**В карточках есть инфографика.** Баннер размерной сетки PLUS SIZE вшит в
десятки карточек и побайтово одинаков. Это не съёмка вещи, и без отдельного
флага `is_template` он склеивал три десятка несвязанных товаров в одну группу.

**Цветовые варианты и plus-size линейка — один крой.** 3220 папок дают 1869
кроёв по названию и 1813 групп после склейки по общим студийным кадрам.
Разбиение по папкам увело бы разные расцветки одной вещи в разные сплиты.

## Структура

```
posefit/
  paths.py      конфиг и пути; preproc_root отделён от локального кэша
  canon.py      якорная схема: канонические координаты тела и скелет
  reliability.py якорная схема: корзины надёжности пар
  arch.py       флаги архитектуры (без torch, для --dry-run)
  model.py      CatVTON поверх SD 1.5 inpainting и дополнения якорной схемы
  catalog.py    разбор info.csv, нормализация кроя, отображение категорий
  manifest.py   блок B: инвентаризация в две таблицы
  qc.py         блок C: резкость, phash, хэш содержимого, признаки фона
  dedup.py      шаблоны, надёжность метки, склейка кроёв
  splits.py     блок F: train/val/test по группам, проверка утечки

```

## Перенос на другую машину

`data/` (8.8 ГБ) и `cache/` в git не лежат — выгрузку надо доставить отдельно.
Дальше на целевой машине: `make venv`, `make check` (вывод целиком нужен для
фиксации версий), `make data`, `make labeling`. Манифест пересобирается на
месте и детерминирован: сплиты совпадут с локальными при том же seed.

## Обучение

Схема CatVTON поверх SD 1.5 inpainting: вещь и человек склеиваются по ширине
в одну картинку, маска закрывает только половину с человеком, и внимание внутри
UNet само переносит фактуру из правой половины в левую. Обучаются только
проекции self-attention — около 50 млн параметров вместо 860 млн, что и делает
возможным обучение на одной 24-гигабайтной карте.

Три конфигурации отличаются **только составом пар**:

| конфигурация | пар | из них wild |
|---|---|---|
| `studio` | 7114 | — |
| `studio_wild` | 9723 | 2609 |
| `studio_clean` | 8027 | 913 |

```bash
python scripts/train.py --config-name studio
python scripts/evaluate.py --run runs/studio
```

Пара `studio_wild` против `studio_clean` — предмет работы: что важнее, объём
шумного надзора или его чистота. Обучение возобновляемо (`--resume`),
гиперпараметры общие в `configs/train.yaml`.

Замер парный, на 373 вручную подтверждённых парах из `cache/test_set.parquet`:
SSIM, LPIPS и FID. Автоматически отобранные пары для оценки не годятся — в них
около 20% неверных расцветок, и метрика мерила бы шум фильтра.

## Якорная схема (ветка `feature/anchor`)

Базовая линия отвечает на вопрос «какие пары оставить». Якорная схема ставит
его иначе и меняет модель, а не выборку. Три дополнения к CatVTON, все с
нулевой инициализацией: на нулевом шаге модель тождественна базовой, обучение
идёт на той же карте с тем же бюджетом памяти, и любой выигрыш относится на
счёт дополнений, а не другого стартового состояния.

**Общее поле координат тела для обеих половин склейки** (`posefit/canon.py`).
В CatVTON внимание должно само найти, какой участок вещи отвечает какому
участку тела, только по фактуре: позиционные коды у половин разные, а поза в
отзывах гуляет. Здесь UNet получает три дополнительных входных канала — карту
(u, v) в «системе торса» и скелет. У человека система строится аффинно по
плечам и бёдрам из позы (левое плечо u=+0.5, плечи v=0, бёдра v=1), у плоской
выкладки — по габаритам вещи и приору пропорций группы одежды (ворот на v=0,
подол футболки на v≈1.3, брюки от v=0.9). Плечо человека и плечо футболки
получают близкие координаты. Это позиционный код, общий для референса и цели,
внутри concat-схемы: без warping-модуля и без отдельного энкодера вещи, как в
IDM-VTON или OOTDiffusion. Стоимость — три канала в `conv_in`.
Координата привязана к телу, а не к кадру: на виде со спины ось u зеркалится
относительно кадра, левый рукав остаётся левым.

**Надёжность пары как условие, а не фильтр** (`posefit/reliability.py`).
Пары не отбрасываются: каждой приписывается корзина — studio, wild_clean,
wild_mid, wild_noisy по `colour_rank` (граница wild_clean совпадает с отбором
`studio_clean`, тест это закрепляет) — и токен корзины подаётся в UNet через
временной эмбеддинг, тем же путём, что и шаг диффузии. Шумные отзывы учат
модель телам и позам, а ошибка расцветки объясняется токеном «шумная пара» и
не переносится на чистые. На выводе всегда токен «студия». Десятая часть
токенов при обучении заменяется на «неизвестно»: это даёт на выводе guidance
по надёжности по образцу classifier-free guidance
(`--reliability-guidance 2`).

**Вектор вещи через тот же путь.** DINOv2-эмбеддинг вещи со стадии `embed`
прибавляется к временному эмбеддингу через нулевой линейный слой:
глобальная подсказка о расцветке и фактуре без обучения кросс-внимания.
Само по себе новизной не является, включается флагом для абляции.

Всё сверх self-attention — 0.2 млн параметров. Схема и каждая компонента
включаются в `configs/train.yaml` (`arch:`) или флагом:

```bash
python scripts/train.py --config-name studio_wild --arch anchor     # runs/studio_wild_anchor
python scripts/evaluate.py --run runs/studio_wild_anchor
python scripts/evaluate.py --run runs/studio_wild_anchor --reliability-guidance 2
python scripts/inspect_guide.py --n 6      # контактный лист карт координат
python scripts/compare_runs.py runs/studio_wild runs/studio_wild_anchor
```

Замер берёт схему из снимка `train_config.yaml` прогона и собирает те же
модули до загрузки весов. Абляция: `arch.guide`, `arch.reliability`,
`arch.garment_embed` выключаются по одному; главное сравнение —
`studio_wild_anchor` против `studio_wild` и `studio_clean` на тех же 373 парах.

Что следует проверить перед защитой: утверждение о новизне опирается на то,
что общий координатный код для референса и цели в concat-диффузии и условие
по надёжности пары в VTON в литературе не встречались; это нужно подтвердить
поиском по работам 2024–2026 годов.

## Что дальше

Не сделано и требует решений:

* **разметка** — `make labeling` собирает `cache/labeling/garment.html` и
  `wild.html`: по 250 кадров, выборка пропорциональна группам одежды и берётся
  только из train, чтобы пороги не оказались подогнаны под тест. Файлы
  самодостаточные (миниатюры внутри), размечаются с клавиатуры, прогресс
  переживает перезагрузку, кнопка выгружает CSV. В них кадры реальных
  покупателей — файлы остаются локальными и никуда не публикуются;
* **блок D** — классификатор «плоская выкладка / кадр на модели». Приор
  `is_last_product` и признаки фона уже в манифесте; нужен детектор лица
  (`cv2.FaceDetectorYN`), порог калибруется по `labels_garment.csv`;
* **wild-фильтр** — человек в кадре, торс виден, резкость, совпадение
  расцветки; калибруется по `labels_wild.csv`;
* **сборка пар** — `manifest_pairs.parquet` для студийной и wild-веток;
* **первый прогон** — обучающий код написан вслепую, на машине без GPU, и
  ни разу не исполнялся; первые запуски наверняка потребуют правок;
* **latents** — стадия не запускалась намеренно: она привязана к VAE
  выбранного бэкбона и пересчитывалась бы при смене архитектуры.
